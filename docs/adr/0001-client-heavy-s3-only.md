# ADR-0001：客户端重、服务端只用 S3 兼容存储

- 状态：已接受
- 日期：2026-10-29

## 背景

目标用户是自托管的个人开发者，希望“一台自己的服务器、一条命令部署”。自研后端意味着用户要运维一个持续演进的服务，并承担升级与兼容成本。

## 备选方案

1. **自研服务端**（API + 数据库 + 存储）：功能最灵活（推送通知、配对、Web 界面），但运维负担重。
2. **只用 S3 兼容存储**：所有逻辑在客户端；服务端可以是 RustFS、Garage、SeaweedFS 或已有的 AWS S3、R2、OSS。
3. **点对点直连**：不需要服务器，但两台机器很少同时在线，且公司网络通常不允许入站连接。

## 决定

选择方案 2。服务端只有 S3 兼容存储加 Caddy（HTTPS）。并发控制依赖 S3 条件写（`If-None-Match` / `If-Match`），不支持时降级为乐观并发。

## 后果

- 部署与运维极简，用户可以直接使用已有对象存储。
- 配对码、每设备独立凭证、推送通知、Web 界面无法在 v0.1 提供，放到 v0.3 的可选轻量服务端（见 PRD D-02）。
- 需要在登录时探测存储能力，并为不支持条件写的存储实现降级路径。
