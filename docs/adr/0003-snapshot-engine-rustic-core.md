# ADR-0003：快照引擎使用 rustic_core

- 状态：已接受
- 日期：2026-10-29

## 背景

推送需要内容寻址分块、去重、客户端加密、快照历史、断点续传。这些能力自研周期长、风险高，且任何缺陷都可能导致数据丢失。

## 备选方案

1. **rustic_core**（Rust 库，restic 兼容格式）：可直接编译进单文件二进制；格式成熟，可用 restic 官方工具应急恢复；`rustic_backend` 基于 OpenDAL，与存储访问选型一致。缺点是尚未 1.0（当前 0.13.x）。
2. **kopia**（Go）：功能成熟，但只能作为外部进程调用，需随安装包分发第二个二进制，与“单文件二进制”目标冲突。
3. **自研格式**：完全可控，但开发与验证成本最高。

## 决定

选择 rustic_core，并锁定版本；在 `workroam-snapshot` crate 中定义 `SnapshotEngine` 接口，业务代码只依赖接口。

## 后果

- 用户数据不会被锁死在 Workroam 中：即使 Workroam 不可用，也能用 restic 读取仓库。
- 恢复密钥可以作为仓库中的额外密钥文件实现，修改密码无需重新加密数据。
- 升级 rustic_core 需要经过集成测试与故障注入测试；如上游停滞，可通过接口替换实现。
