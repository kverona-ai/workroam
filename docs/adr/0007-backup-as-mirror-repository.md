# ADR-0007：备份目标是共用主密钥的独立仓库

- 状态：已接受
- 日期：2026-10-29

## 背景

快照历史和工作区放在同一个存储桶里，能防误删误改，但防不了存储本身出事：桶被误删、存储损坏、服务商停服、主存储密钥被盗后数据被删。用户需要把工作区再保存一份到另一个地方，并且在主存储整体丢失时能把整个工作区恢复出来。备份目标必须保持端到端加密，并能用用户已有的加密密码或恢复密钥解锁。

## 决定

- 备份目标是另一个 rustic 仓库，放在另一个 S3 兼容桶或本地目录中。初始化时沿用主仓库的分块参数，并用同一个主密钥，由加密密码和恢复密钥各包装一个密钥文件。
- 由一台维护设备定期把各项目的最新快照复制到备份仓库，再写入一个恢复点。恢复点是当时控制对象的副本，不含访问密钥和租约。
- 保留策略作用于恢复点，备份仓库只保留仍被恢复点引用的快照。
- 主存储整体丢失时，可以把备份目标提升为主存储，也可以把某个恢复点复制到新桶。
- 更换主存储通过 `control/moved` 指针完成，其他设备下次同步时自动跟随。

## 后果

- 备份和主存储用同一个密码或恢复密钥解锁；项目 ID 与控制对象两边一致，恢复时不需要重新计算。
- 数据块按 ID 去重，复制时不需要重新分块；存储迁移是对象级复制，不需要解密和重新加密。
- 修改加密密码时，必须同时更新每个备份仓库中的密钥文件，这项工作由维护设备负责。
- 只有一台维护设备写备份仓库，没有并发写入问题；维护设备长期离线时需要改派。
- 备份目标的凭证只在维护设备的密钥库和加密的控制对象中。主存储密钥被盗不会波及备份；建议备份桶开启版本控制或对象锁定，作为最后一道防线。
