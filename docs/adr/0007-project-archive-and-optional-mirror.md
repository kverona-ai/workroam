# ADR-0007：项目归档保存在同一个仓库中，异地备份只做可选的对象级镜像

- 状态：已接受
- 日期：2026-10-29

## 背景

项目做完后，用户可能希望停止同步，但把项目永久留存，以后需要时（例如运维期出现新需求）再恢复继续开发。是否归档由用户决定。存储中本来就保存着每个项目的加密快照，误删和改坏都可以从快照历史找回；只有存储本身整体丢失时，才需要存储之外的第二份副本。

## 决定

- 归档是同一个加密仓库中的一个带 `workroam:archived` 标签的快照，加上一条加密的归档记录。归档快照为每个代码仓库生成完整 bundle，不依赖增量链、origin 或中转库，可以独立恢复。
- 快照清理跳过归档快照。默认只保留归档时的最终状态，用户可以选择保留完整历史。
- 归档只改变项目的同步状态，不删除、不移动、不修改任何设备上的本地文件，也不会自动发起。
- 恢复时，如果本机已有项目文件夹，直接恢复同步；没有则从归档还原。规则、MCP 与 Skills 只保存定义源，恢复时按当前适配器重新生成。
- 异地备份是可选功能（v0.3），实现为整个前缀的对象级镜像：只复制新增对象，删除延迟 30 天，凭证只在执行镜像的设备本机。

## 后果

- 归档与其他项目共享去重，几乎不额外占用空间；归档包导出（v0.3）满足离线保存的需要。
- 归档快照需要生成完整 bundle，大仓库归档一次耗时较长。
- 不开启异地备份时，存储整体丢失无法恢复；使用云对象存储时由服务商的多副本保证，自建单盘存储时文档建议开启。
- 镜像和主存储共用密钥文件，用同一个加密密码或恢复密钥即可解锁；修改密码后，旧密钥文件在删除延迟期内仍留在镜像中。
